# litagent — агент поиска и легального скачивания научных статей

Два режима:

- **manual** — вы задаёте темы и ключевые слова, агент ищет по нескольким источникам, склеивает дубли и скачивает открытые копии.
- **auto** — вы описываете цель обычным языком, **локальная LLM** (Ollama / LM Studio / llama.cpp) строит запрос и выбирает источники с учётом пометок из вашего `.tex`-файла, при необходимости уточняет план по результатам и фильтрует выдачу по релевантности.

Без внешних зависимостей: только стандартная библиотека Python ≥ 3.11.

| Команда | Что делает |
| --- | --- |
| `manual` | ручной поиск по темам и ключевым словам |
| `auto` | поиск по цели на естественном языке (локальная LLM) |
| `check` | проверить источники и LLM из вашей сети |
| `notes` | показать, что агент извлёк из вашего `.tex` / `.md` |
| `sites` | свои сайты для поиска (`add`, `edit`, `remove`, `show`, `test`, `import`, `list`) |
| `preset` | пресеты ручного режима: `list`, `show`, `remove` |
| `organize` | разложить уже скачанные файлы по папкам источников |
| `clean` | очистить папку со скачанными статьями |
| `help` | справка по темам: `python -m litagent help <тема>` |

У каждой команды есть `-h`.

## Быстрый старт

```bash
cp litagent.example.toml litagent.toml      # впишите email и ключи
export LITAGENT_EMAIL=you@example.org
export OPENALEX_API_KEY=...                 # бесплатный; без него OpenAlex пропускается
python -m litagent check                    # проверить источники и LLM из вашей сети
python -m litagent manual -q "graph neural networks" -n 25    # скачать 25 статей с PDF
```

Ключи (все бесплатные, все необязательны, кроме OpenAlex и CORE): `NCBI_API_KEY`, `OPENALEX_API_KEY`, `S2_API_KEY`, `CORE_API_KEY`. Источник без обязательного ключа просто пропускается с пояснением.

## Почта и контекстный файл

* **Почта** (обязательна для реальных запросов; уходит в User-Agent, Crossref `mailto`, Unpaywall, NCBI) задаётся одним из способов:
  `--email you@real.org`, переменной `LITAGENT_EMAIL`, либо строкой `email = "you@real.org"` в `litagent.toml`
  (создать: `cp litagent.example.toml litagent.toml` и поправить). В `.tex` почту писать не нужно: `you@example.org` там только в примерах кода.
* **Контекстный файл** (`literature_search_systems.tex`) агент читает как текст, **компилировать его для работы не нужно**.
  PDF для чтения глазами: `latexmk -xelatex literature_search_systems.tex` (нужен именно XeLaTeX: пакеты `fontspec` и `polyglossia`).

## Ручной режим

Мини-язык темы: `;` или `,` — И, `|` — ИЛИ внутри группы, `-слово` — исключить. Многословные термины автоматически становятся фразами.

```bash
# одна тема
python -m litagent manual -q "CRISPR; sickle cell disease | SCD; -review" --year-from 2020 --oa-only

# несколько тем, файл тем (по строке на тему, # — комментарий)
python -m litagent manual --topics-file topics.txt --sources pubmed,europepmc,openalex --limit 100 --max-downloads 50

# посмотреть, какие запросы уйдут в каждый источник, ничего не отправляя
python -m litagent manual -q "retrieval augmented generation" --arxiv-cat cs.CL --dry-run

# родной синтаксис конкретного источника поверх общего
python -m litagent manual -q "asthma" --raw 'pubmed="asthma"[mh] AND child[tiab]'

# только найти, не скачивать
python -m litagent manual -q "graph neural networks" --no-download

# скачать ровно 30 статей с PDF: искать, пока не наберётся (см. «Скачать N статей»)
python -m litagent manual -q "graph neural networks" -n 30
```

Ключевые опции: `--sources`, `--limit` (на источник), `--year-from/--year-to`, `--oa-only`, `--title-only`, `--strict` (локально требовать каждую группу терминов), `--group "a|b"`, `--exclude "x|y"`.

Опции скачивания: `--max-downloads N` (потолок за запуск), `-n/--count N` (добрать ровно N PDF, см. ниже), `--pdf-only` (только статьи с реальным PDF), `--workers N` (потоков), `--no-download` (только найти).

## Пресеты ручного режима

Сложный запрос можно сохранить под именем и запускать одной опцией:

```bash
# сохранить и сразу выполнить (с --dry-run — только сохранить, ничего не отправляя)
python -m litagent manual -q "graph; neural|gnn; -survey" --year-from 2020 \
    --sources pubmed,openalex -n 30 --save-preset gnn --preset-desc "GNN за последние годы" --dry-run

python -m litagent manual --preset gnn                    # запустить
python -m litagent manual --preset gnn -q "attention"     # + ещё одна тема к темам пресета
python -m litagent manual --preset gnn --year-from 2023   # значение из командной строки главнее
python -m litagent preset list                            # имена и описания
python -m litagent preset show gnn                        # параметры и эквивалентная команда
python -m litagent preset remove gnn
```

- Пресеты лежат в `presets.json` рядом с запуском (другой файл: `--presets-file` или `presets_file` в `litagent.toml`). Это обычный JSON, его можно править руками.
- В пресет попадает всё, что описывает поиск: темы (`-q`, `--topics-file`), `--group`, `--exclude`, `--raw`, `--arxiv-cat`, источники (`--sources`/`--site`), годы, `--limit`, `--oa-only`, `--title-only`, `--strict`, `--pdf-only`, `-n/--count`, `--max-downloads`, `--workers`, `--flat`. E-mail, ключи и пути (`--out`, `--config`, `--sites-file`) не сохраняются.
- Правила слияния при `--preset`: списки (`-q`, `--group`, `--exclude`, …) **дополняются** (сначала пресет, затем командная строка); значения из командной строки заменяют пресетные; выбор источников (`--sources`/`--site`) и числа статей (`--count`/`--max-downloads`) из командной строки заменяет соответствующие настройки пресета целиком. Включённый в пресете флаг (например `--oa-only`) из командной строки выключить нельзя: сделайте отдельный пресет.
- `--save-preset` с уже существующим именем перезаписывает пресет. Пресет обязан содержать хотя бы одну тему.

## Авто-режим

```bash
ollama pull gemma4          # модель по умолчанию; адрес по умолчанию http://127.0.0.1:11434
python -m litagent auto "Найти свежие статьи про CRISPR при серповидноклеточной анемии, только открытый доступ" \
    --notes literature_search_systems.tex --llm-filter

# LM Studio / llama.cpp server
python -m litagent auto "..." --llm-provider openai --llm-url http://localhost:1234/v1 --model my-model

# другая модель или адрес Ollama
python -m litagent auto "..." --model gemma4 --llm-url http://127.0.0.1:11434

# посмотреть план модели и итоговые запросы без поиска
python -m litagent auto "..." --notes literature_search_systems.tex --dry-run
```

Что происходит:

1. `notes.py` разбирает ваш `.tex`: строки карточек систем (синтаксис запросов, подводные камни, лимиты, блокировки), блоки `warnbox/notebox` и комментарии вида `% AGENT: ...`. Команда `python -m litagent notes файл.tex` показывает, что именно извлечено (это то, что видит модель). Можно добавить свои `.md/.txt` с пометками (они идут в промпт как «высший приоритет»).
2. LLM получает цель, список доступных источников, жёсткие правила и пометки только по этим источникам, и возвращает JSON-план: группы терминов (AND между группами, OR внутри), исключения, годы, OA, источники, при необходимости «сырой» запрос.
3. План **валидируется кодом**: запрещённые и неизвестные источники отбрасываются, строки чистятся и режутся по длине, годы и лимиты ограничиваются. Нельзя заставить агента ходить в Google Scholar или на страницы сайта PMC, даже если модель так «решит».
4. Поиск → дедупликация. Затем (если `--rounds` ≥ 2) модель смотрит на сводку результатов (сколько найдено, `querytranslation` PubMed, примеры названий) и либо подтверждает, либо присылает уточнённый план.
5. `--llm-filter`: модель ставит 0–10 релевантность по названию и аннотации, ниже `--min-score` отсекается, остальное ранжируется по оценке.
6. Если LLM недоступна или отвечает мусором, агент сам переключается на эвристику (ключевые слова, «последние N лет», «открытый доступ»); кириллица без LLM не переводится — для англоязычных баз это даст плохую выдачу, и агент об этом предупредит.

## Скорость скачивания

Скачивание идёт параллельно, но вежливо к серверам; мёртвый или медленный хост не тормозит весь запуск:

* **Параллельно, но вежливо.** По умолчанию 4 потока (`--workers N`, `download_workers` в `litagent.toml`, `1` = по одному). Запросы к разным
  хостам идут одновременно, а к одному хосту по-прежнему не чаще `min_interval` и **одно соединение за раз**. Скользящее окно считает
  «успешные + в работе», поэтому сверх `--max-downloads` ничего не качается; провалы тут же заменяются следующими кандидатами.
* **Быстрый отказ при скачивании файлов:** 2 попытки вместо 5, таймаут 25 с (`download_retries`, `download_timeout`); сервер просит ждать
  дольше 20 с (Retry-After) — кандидат пропускается, а не ждётся. Обычные запросы поиска и API ведут себя как раньше.
* **Автомат для мёртвых хостов:** 3 сбоя скачивания подряд — хост пропускается до конца запуска (404 и «не PDF» сбоями не считаются).
* **Ранний обрыв заглушек:** если в первом куске ответа нет `%PDF` (лендинг, paywall), скачивание прерывается сразу, а не после мегабайтов.
* В конце печатается, сколько заняло скачивание, потоков, запросов и повторов.

На локальном стенде с искусственной задержкой (6 хостов × 3 статьи, 300 мс на ответ): 1 поток 5,4 с, 2 потока 2,7 с, 4 потока 1,5 с, 8 потоков 0,9 с.
Реальный выигрыш зависит от того, на скольких разных хостах лежат файлы: если почти всё на одном хосте (например, FTP PMC), оно
останется последовательным по правилам вежливости. Переиспользование соединений (keep-alive) не реализовано.

## Только статьи с полным PDF

```bash
python -m litagent manual -q "тема" --pdf-only --max-downloads 10
python -m litagent auto "цель" --pdf-only          # в litagent.toml: pdf_only = true
```

Обычный `--oa-only` лишь фильтрует по признаку «открытый доступ», а PDF при этом может не найтись (лендинг, только XML, битая ссылка).
`--pdf-only` считает статью найденной, **только если PDF реально скачан и проверен** (не лендинг и не paywall):

* включает `--oa-only`, поэтому источники сразу сужают выдачу (PubMed: `free full text[sb]`, Europe PMC: `OPEN_ACCESS:y`);
* XML-копии (Europe PMC) не запрашиваются, а ранее сохранённый XML за «PDF уже есть» не считается;
* сначала проверяются записи, где PDF вероятен (ссылка из источника, PMCID, `is_oa`), внутри групп порядок по релевантности сохраняется;
  цель — `--max-downloads` статей с PDF, попыток не более 10 × `max_downloads` (обычно 4 ×);
* в `results.csv` попадают только статьи с PDF; отброшенные (с причиной) и счётчики лежат в `run.json` → `pdf_only`;
* проверка = скачивание, поэтому с `--no-download` режим несовместим.

Если в базе слишком мало открытых PDF, статей с PDF будет меньше `max_downloads`. Чтобы агент сам искал глубже, пока не наберёт нужное число, используйте `--count` (следующий раздел).

## Скачать N статей (`--count`)

```bash
python -m litagent manual -q "graph neural networks" -n 30                  # 30 статей с PDF
python -m litagent auto "свежие статьи про CRISPR" --count 50 --deepen-rounds 8
```

`-n N` / `--count N` — «скачать **ровно N статей с PDF**». Это `--pdf-only` + `--max-downloads N` плюс автоматическая докачка:

1. Агент делает обычный поиск (`--limit` записей на источник) и скачивает кандидатов, пока не наберётся N PDF.
2. Если кандидаты кончились, а N не набрано, поиск **углубляется**: тот же запрос повторяется с лимитом на источник ×2 (50 → 100 → 200 …, не выше `deepen_limit_cap`, по умолчанию 1000). Уже проверенные записи пропускаются, проверяются только новые.
3. Так повторяется не более `--deepen-rounds K` раз (по умолчанию 5; `0` — без углубления). Остановка раньше срока: N набрано или глубже источники ничего нового не отдают.
4. В авто-режиме углубляется последний план модели (те источники, которые реально сработали в последнем раунде); если включён `--llm-filter`, новые записи тоже проходят фильтр.

Правила вежливости действуют и при докачке: паузы по хостам, `Retry-After`, остановка на 401/403 и запрет на нелегальные источники. Часть повторных запросов выдачи берётся из HTTP-кэша, но углубление всё равно делает дополнительные обращения к API, так что для больших N заводите ключи (`NCBI_API_KEY`, `S2_API_KEY` и т. д.). Если N не набрано, агент так и пишет («Набрано X из N PDF») и подсказывает, что сделать: добавить источники, расширить тему или годы, увеличить `--deepen-rounds`. Итог (`requested`, `reached`, `candidates`) сохраняется в `run.json` → `target`.

Настройки по умолчанию — в `litagent.toml`: `max_downloads`, `deepen_rounds`, `deepen_limit_cap`.

Когда `--count` не нужен: если достаточно «не более N файлов, любых», берите `--max-downloads N` — он не углубляет поиск и допускает XML-копии.

## Только один сайт

```bash
python -m litagent manual -q "graph neural network" --site mysite     # встроенный или свой сайт из custom_sites.json
python -m litagent auto "цель" --site pubmed                           # нейросеть видит в контексте только его
python -m litagent manual -q "тема" --pick-site                        # список с номерами, выбираете один
```

`--site` и `--pick-site` нельзя сочетать с `--sources`. Свой сайт можно выбрать, даже если он выключен по умолчанию.
В авто-режиме в промпт попадает только выбранный сайт (с пометкой, что поиск ограничен им), плана на другие источники не будет.
Недоступные сайты (Google Scholar и т. п.) называются прямо, с причиной.

## PubMed и PMC

`pubmed` теперь ищет в двух базах одним запросом: PubMed (аннотации) и **PMC** (полнотекстовый архив, E-utilities `db=pmc`).
Записи объединяются по PMID/DOI/PMCID; `--dry-run` показывает оба запроса. PMC-часть строится из терминов (`[Title]`/`[Abstract]`,
годы `[pdat]`); сырые запросы в синтаксисе PubMed (`[mh]`, `[pt]`) уходят только в PubMed. Если PMC не знает какой-то тег поля,
запрос автоматически повторяется без тегов (годы тогда фильтруются локально); сбой PMC-части не роняет результаты PubMed.

Скачивание PDF для записей с PMCID идёт **только официальным путём**: OA Web Service (`oa.fcgi?id=PMC…`) -> прямая ссылка на PDF
или пакет статьи на `ftp.ncbi.nlm.nih.gov` (по https); из пакета берётся основной PDF (приложения `supp*`, `media*` и т. п. пропускаются;
если «основных» несколько, берётся самый большой, это эвристика). Работает только для статей из Open Access Subset; для остальных
остаются Unpaywall и Europe PMC XML. Сайт PMC агент не открывает: массовая загрузка оттуда запрещена. Одиночные PDF из `oa_pdf`
PMC разрешает для некоммерческого использования.

Отключить: `--no-pmc` или `pubmed_pmc = false` в `litagent.toml` (тогда PubMed ищет только в PubMed и PDF из PMC не качает).
Лимит `--limit` применяется к каждой из двух частей отдельно (до дедупликации).

## Свои сайты для поиска

Любой сайт с официальным API, который отдаёт JSON по GET, можно добавить без правки кода — через опросник:

```bash
python -m litagent sites add            # вопросы-ответы; в конце покажет, что увидит нейросеть, и спросит «Сохранить?»
python -m litagent sites list           # встроенные + свои
python -m litagent sites edit mysite    # тот же опросник, прежние ответы подставлены по умолчанию (Enter — оставить, «-» — очистить)
python -m litagent sites show mysite    # JSON-описание и текст для нейросети
python -m litagent sites test mysite    # реальный запрос «machine learning» и проверка, что поля разобраны
python -m litagent sites remove mysite
python -m litagent sites import https://example.org/sites.json   # список сайтов из интернета (см. ниже)
python -m litagent help                 # встроенная справка по темам: help sites, help presets, help import, help clean …
```

Опросник спрашивает: имя, что это за база, адрес API, параметр с поисковой строкой, постоянные параметры, синтаксис
(булевы операторы или простые слова), фильтры по годам и открытому доступу, страницы, API-ключ, паузу между запросами,
пути к полям в ответе и свои пометки. После адреса и параметров может сделать **пробный запрос** и сам предложить пути
к списку статей и полям (названия, авторы, год, DOI, аннотация, PDF…), вам останется подтвердить Enter-ом.

* **Файл для ручного режима.** Все сайты лежат в `custom_sites.json` (создаётся при первом `sites add`; путь — `--sites-file`
  или `custom_sites` в `litagent.toml`). Ручной режим читает оттуда URL, имя параметра, операторы и пути в JSON, поэтому
  `manual -q "тема" --sources mysite` работает так же, как со встроенными источниками; `--dry-run` покажет итоговый запрос.
  Сайты, у которых включено «использовать автоматически», подключаются сами, если `--sources` не задан.
* **Контекст нейросети.** В авто-режиме описание каждого доступного своего сайта автоматически попадает в системный промпт:
  что это за база, адрес, в какой параметр класть запрос, синтаксис и операторы, фильтры, страницы, ключ и ваши пометки.
  Модель выбирает сайт по теме и строит запрос именно в этом формате; код всё равно валидирует план.
* **Безопасность.** Адрес проверяется политикой (`policies.json`: Sci-Hub, Google Scholar и прочее блокируются), нужен https
  (http — только localhost), HTML-выдача не разбирается, ответ не-JSON считается ошибкой. Ключ в файл не пишется: только имя
  переменной окружения (или `[keys]` в `litagent.toml` под именем сайта). Пауза между запросами к хосту берётся из вашего ответа.
* Поддерживается только GET; сайты с POST/OAuth/подпиской требуют отдельного адаптера (см. «Расширение»).

### Загрузка списка сайтов из интернета

```bash
python -m litagent sites import https://…/sites.json          # или путь к локальному файлу
python -m litagent sites import URL --only goodsite,2 --enable   # только выбранные (имена или номера из списка)
python -m litagent sites import URL --enable --overwrite -y    # все сразу: включить, перезаписать совпадающие имена, без вопроса
```

Формат файла тот же, что у `custom_sites.json` (образец: `custom_sites.example.json`; для GitHub нужна ссылка «Raw»).

* **Экономно:** один GET, не более 256 КБ, без кэша и повторов, до 50 сайтов за раз; паузы по хосту и блок-лист работают как везде.
* **Выбор сайтов.** Список печатается с номерами; на вопрос «Что добавить?» — Enter берёт все, а `1,3`, `2-4` или имена через запятую
  берут только их, «нет» отменяет. Заранее то же задаёт `--only`; `-y` без `--only` добавляет все.
* **Файл из сети недоверенный:** сначала печатается список (имя, хост, статус), запись — только после вашего выбора; ключи из файла вырезаются
  (иначе чужой файл мог бы отправить ваш секрет на чужой хост — настройте ключ сами через `sites edit`); тексты чистятся и
  режутся, потому что попадают в промпт модели; сайты приходят **выключенными** (включить: `--enable` или `sites edit`);
  пауза между запросами — не меньше 1 с; имена встроенных источников и существующие имена не перезаписываются без `--overwrite`.
* Откуда пришёл сайт, видно в `sites list` (`<- адрес`).

## Очистка папки со статьями

```bash
python -m litagent clean                # покажет, сколько файлов и мегабайт, и спросит подтверждение («да»)
python -m litagent clean --dry-run      # только показать
python -m litagent clean -y             # без вопроса
python -m litagent clean --all          # + отчёты запусков (runs/) и HTTP-кэш
```

Удаляются скачанные `.pdf`, `.xml` и недокачанные `.part` из `pdf/` и `xml/`. В папках источников удаляются только файлы, созданные агентом (имя вида `Автор_Год_Название_хеш.pdf`); ваши собственные файлы остаются, пустые папки источников убираются.
`index.json` приводится в соответствие с диском, поэтому удалённые статьи при следующем запуске скачиваются заново.
Если указанная папка не похожа на библиотеку litagent (нет `pdf/`, `xml/`, `index.json`), команда ничего не делает.

## Что агент соблюдает всегда (`policies.json`)

- Только официальные API; HTML-страницы выдачи не разбираются; CAPTCHA, ротация IP и подмена User-Agent не используются.
- Паузы по хостам (arXiv 3.1 с, PubMed 0.34 с / 0.11 с с ключом и т. д.), `Retry-After` на 429/503, кэш ответов на диск.
- **401/403 = стоп для этого хоста до конца запуска**, без повторов.
- Файлы только из легальных открытых источников: ссылки самих баз, Unpaywall, Europe PMC `fullTextXML`, PMC OA Web Service (см. «PubMed и PMC»). Скачанное проверяется (`%PDF` / XML): лендинги и paywall отбрасываются.
- arXiv-ссылки автоматически переписываются на `export.arxiv.org`; страницы сайта PMC (`pmc.ncbi.nlm.nih.gov`, `/pmc/articles/…`), Google Scholar, «теневые библиотеки» заблокированы паттернами; открыты только официальные каналы PMC: `oa.fcgi` и `ftp.ncbi.nlm.nih.gov` по https.
- Не реализованы (нет открытого доступа или нужна подписка): Google Scholar, eLIBRARY.RU, КиберЛенинка, BASE, Scopus, Web of Science, IEEE.

## Результаты на диске

```
library/
  pdf/<источник>/       скачанные PDF по папкам сайтов-источников (Автор_Год_Название_хеш.pdf)
  xml/<источник>/       то же для XML-копий (Europe PMC)
  index.json            что уже скачано — повторный запуск не качает заново
  runs/<время>/run.json точные запросы, translation PubMed, ошибки, раунды LLM, статистика HTTP
  runs/<время>/results.csv  все найденные записи со статусом скачивания
  .http_cache/
```

### Папки источников

Файлы раскладываются по папкам с названием сайта, который нашёл статью:

```
library/pdf/
  openalex/   Smith_2023_Graph_neural_networks_1a2b3c4d.pdf
  pubmed/     ...
  arxiv/      ...
  mysite/     ...        ← ваш сайт из custom_sites.json получает свою папку автоматически
```

- Название папки — имя источника (для своего сайта — его имя из `custom_sites.json`, приведённое к латинице, нижнему регистру и `_`). Если статью нашли несколько источников, она кладётся в папку первого из них (в порядке, заданном `--sources` или `sources` в конфиге). Если у записи нет источника, папка называется `unknown`.
- Дубликаты не плодятся: индекс `index.json` один на всю библиотеку, а повторный запуск видит файл в любой папке.
- Папка создаётся только тогда, когда в неё что-то скачано; в конце запуска агент пишет, сколько PDF лежит в каждой папке.
- Старая плоская библиотека продолжает работать. Чтобы разложить уже скачанное: `python -m litagent organize` (сначала можно `--dry-run`).
- Отключить разбивку: `--flat` для одного запуска или `folders_by_source = false` в `litagent.toml`.

Статусы: `pdf`, `xml`, `exists` (уже в библиотеке), `no_oa` (нет открытых копий), `no_pdf` (только XML или PDF не нашёлся, в режиме `--pdf-only`), `failed: ...`, `skip:not_oa`.

## Важное про проверку

Адаптеры написаны по документации и вашему обзору, но **живые запросы к сервисам из этой среды не выполнялись** (исходящая сеть закрыта). Перед работой запустите `python -m litagent check`: для каждого источника это один запрос и понятный статус. Лимиты у OpenAlex, Crossref, Semantic Scholar, CORE в обзоре помечены как противоречивые или вторичные; при расхождениях правьте интервалы в `policies.json`.

## Расширение

Новый источник — класс в `sources.py` с `build_query()` и `search()` плюс запись в `policies.json` (`intervals`, `sources.<имя>.about/hint`). Для сайта с обычным JSON-API класс писать не нужно — достаточно `sites add`. Нужны подписочные базы (Scopus, WoS) — добавляйте адаптер с вашим ключом и токеном института.

## Если что-то не работает

### Авто-режим падает в эвристику

Ollama по умолчанию использует короткое окно контекста и **молча обрезает** длинный промпт (заметки из `.tex` делают его длинным).
Агент сам передаёт `num_ctx` (параметр `[llm] num_ctx`, по умолчанию 8192; при необходимости растёт до 32768),
отключает `think` у «думающих» моделей, ужимает заметки в промпте планировщика и нормализует ответ модели
(регистр/алиасы источников, план внутри `{"plan": …}`, русские термины → повторный запрос на английском).
Если авто-режим всё же уходит в эвристику, причина печатается строкой «LLM не дала план (…)».

### Набрано меньше N статей

Это значит, что у доступных источников закончились статьи с открытым PDF по вашему запросу. Добавьте источники (`--sources`), смягчите тему (уберите `--strict`, `--title-only`, исключения), расширьте годы или увеличьте `--deepen-rounds`. Причины отсева каждой статьи — в `run.json` (`pdf_only.dropped_titles`) и `results.csv`.
